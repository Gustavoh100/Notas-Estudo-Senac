# NOTA DE ESTUDO — AULA 01 | UC-04

## Tema principal

A UC4 tem como objetivo transformar um projeto local em uma **entrega web pública, testada, organizada e documentada**.

> **Ideia principal:** não basta o projeto funcionar no computador. Ele precisa estar preparado para ser publicado e comprovado por meio de testes e evidências.

---

## Objetivos da Aula 01

- Entender o funcionamento da UC4.
- Definir qual projeto será publicado.
- Organizar uma pasta ou repositório de evidências.
- Fazer um diagnóstico inicial do projeto.
- Identificar problemas, pendências e riscos.
- Criar o **Checklist de Publicação v0**.

---

## Local x Produção

### Projeto local

É o projeto que funciona no computador do desenvolvedor.

- Serve para desenvolver e testar.
- Ainda não é uma entrega pública.
- Alguns caminhos e recursos podem funcionar somente naquele computador.

### Projeto em produção

É o projeto publicado em uma hospedagem e acessível por uma URL.

- Pode ser acessado por outras pessoas.
- Imagens, CSS e JavaScript precisam funcionar.
- Links e navegação precisam estar corretos.
- Deve ser testado e comprovado.

**Resumo:**

- **Local:** ambiente de criação.
- **Produção:** ambiente de entrega.

---

## Problemas comuns na publicação

- Imagens não carregarem.
- Links com caminhos errados.
- Diferença entre letras maiúsculas e minúsculas nos nomes dos arquivos.
- Arquivos com espaços, acentos ou caracteres especiais.
- CSS ou JavaScript não carregarem.
- Formulários não funcionarem.
- Site apresentar problemas em telas menores.
- Imagens muito grandes deixarem o site pesado.

---

## Evidências

Na UC4, **não basta dizer que testou, é preciso mostrar**.

### Exemplos de evidências

- Prints de tela.
- Links do projeto.
- Checklists preenchidos.
- Datas e versões.
- Problemas encontrados.
- Correções realizadas.
- Comparações de antes e depois.

---

## Atividade da Aula 01

A primeira atividade é um **diagnóstico inicial do projeto**, não a publicação.

A equipe deve:

1. Escolher ou confirmar o projeto.
2. Definir o objetivo e o público-alvo.
3. Identificar o tipo de projeto.
4. Definir as responsabilidades da equipe.
5. Criar uma pasta ou repositório de evidências.
6. Testar o projeto localmente.
7. Identificar pendências.
8. Listar pelo menos 5 riscos de publicação.
9. Tirar prints do projeto funcionando.
10. Preencher o **Checklist de Publicação v0**.

---

## O que verificar no projeto?

- A página inicial está clara?
- O menu funciona?
- Os links funcionam?
- As imagens, CSS e JavaScript carregam?
- Existem arquivos duplicados ou desnecessários?
- Existem caminhos absolutos que podem causar problemas?
- Existem nomes de arquivos com espaços ou acentos?
- O site funciona em telas menores?
- Existe alguma função que depende exclusivamente do computador local?

---

## Riscos de publicação

Exemplos:

1. Imagens não carregarem por caminhos incorretos.
2. Menu quebrar em telas menores.
3. Arquivos estarem desorganizados.
4. Formulário não possuir destino definido.
5. A hospedagem escolhida não ser compatível com o projeto.

---

## Entrega da Aula 01

A equipe deve entregar:

- Projeto definido.
- Objetivo do projeto.
- Integrantes e responsabilidades.
- Pasta ou repositório de evidências.
- Checklist de Publicação v0.
- Lista de pendências.
- Lista de riscos.
- Prints do projeto funcionando localmente.

---

# UC04 - Aula 02: Definição de Hospedagem

## Objetivo
Escolher uma hospedagem adequada para um projeto web, justificando a decisão com critérios técnicos e de negócio.

---

# Antes de Escolher uma Hospedagem

Responder:

- O projeto usa apenas HTML, CSS e JavaScript?
- Utiliza framework?
- Possui backend?
- Usa banco de dados?
- Tem login, formulários ou painel administrativo?
- Como será atualizado após a publicação?

> Regra: não se escolhe hospedagem antes de entender o projeto.

---

# Publicação na Internet

Ao publicar um projeto, geralmente são necessários:

- Servidor web
- Domínio ou subdomínio
- HTTPS (SSL)
- Permissões de acesso
- Organização de pastas
- Manutenção e atualizações

---

# Tipos de Hospedagem

## 1. Hospedagem Estática

### Indicada para:
- Landing pages
- Portfólios
- Sites institucionais simples
- Projetos sem backend

### Exemplos:
- GitHub Pages
- Netlify
- Vercel
- Cloudflare Pages

### Limitação:
- Não executa backend nem banco de dados próprio.

---

## 2. Hospedagem Compartilhada

### Indicada para:
- Sites simples
- PHP
- WordPress
- Aplicações com MySQL

### Vantagens:
- Baixo custo
- Fácil administração
- Painel visual

### Limitações:
- Menor controle do servidor
- Configurações limitadas

### Exemplos:
- HostGator
- Hostinger
- Locaweb
- KingHost
- GoDaddy

---

## 3. PaaS (Plataforma de Deploy)

A plataforma gerencia a infraestrutura e realiza o deploy automaticamente.

### Indicada para:
- React
- Next.js
- Node.js
- Aplicações modernas
- APIs simples

### Exemplos:
- Vercel
- Netlify
- Render
- Railway
- Heroku

### Limitações:
- Restrições em planos gratuitos
- Cobrança por uso
- Regras da plataforma

---

## 4. VPS (Servidor Virtual)

Maior controle técnico sobre o ambiente.

### Indicada para:
- Backend próprio
- APIs
- Banco de dados
- Docker

### Exige conhecimento em:
- Linux
- SSH
- Nginx ou Apache
- Firewall
- Backup

### Limitação:
- Responsabilidade pela manutenção e segurança.

---

## 5. Servidor Dedicado / Cloud

### Indicado para:
- Projetos grandes
- Alta escalabilidade
- Alto desempenho

### Características:
- Mais controle
- Mais recursos
- Maior custo e complexidade

### Exemplos:
- AWS
- Azure
- Google Cloud
- Oracle Cloud

---

# Critérios de Decisão

Avaliar:

1. Compatibilidade técnica
2. Custo
3. Domínio e HTTPS
4. Facilidade de publicação
5. Manutenção
6. Segurança
7. Limitações
8. Documentação e suporte
9. Adequação ao projeto
10. Possibilidade de atualização

> A melhor hospedagem é a mais adequada ao projeto, não a mais famosa.

---

# Resumo para Revisão

| Tipo | Melhor para | Limitação Principal |
|--------|------------|-------------------|
| Estática | HTML, CSS e JS | Sem backend |
| Compartilhada | PHP e WordPress | Pouco controle |
| PaaS | React, Node e Next | Limites da plataforma |
| VPS | Backend e Docker | Exige conhecimento técnico |
| Cloud/Dedicado | Grandes projetos | Alto custo e complexidade |

## Regra Rápida

- Projeto simples → Hospedagem Estática ou Compartilhada
- Projeto moderno → PaaS
- Projeto com backend próprio → VPS
- Projeto grande e escalável → Cloud/Dedicado
